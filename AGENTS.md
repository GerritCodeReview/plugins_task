# AI Agent Project Profile: task plugin

## What this is

A Gerrit plugin that adds hierarchical task management to code review. Tasks are defined in git-stored config files, evaluated against changes using Gerrit queries, and exposed via the change query API and a Polymer UI component. Task definitions live in `refs/meta/config` or user refs, not in the plugin source itself.

## Build commands

```bash
# Build the plugin JAR
bazel build :task

# Run unit tests
bazel test :junit-tests

# Run a single test class
bazel test :junit-tests --test_filter=com.googlesource.gerrit.plugins.task.TaskExpressionTest

# Run docker-based functional tests (requires Docker)
bazel test :docker-tests

# Lint the JS frontend
bazel test :lint

# Build everything
bazel build :all
```

The built JAR lands at `bazel-bin/task.jar`.

## Code architecture

### Request flow

1. `TaskPluginDefinedInfoFactory` implements `ChangePluginDefinedInfoFactory` — Gerrit calls it when processing a change query or `GET /changes/{id}`. It is the entry point.
2. It creates a `TaskTree`, then for each `ChangeData` walks the tree to produce a `TaskPluginAttribute` (the JSON output attached to each change).
3. CLI options (`--all`, `--applicable`, `--invalid`, `--only`, `--preview`, `--include-paths`, `--include-statistics`, `--evaluation-time`) are parsed via `Modules.MyOptions` and influence what the factory emits.

### Core classes

| Class | Role |
|-------|------|
| `TaskConfig` | Parses a git-stored `.gitconfig`-format task file into POJOs (`Task`, `TasksFactory`, `NamesFactory`, `External`). Extends `VersionedConfigFile`. |
| `TaskConfigCache` | Per-request cache of loaded `TaskConfig` objects; also handles `--preview` masquerading. |
| `Preloader` | Resolves `preload-task` inheritance chains and caches the result by `TaskExpressionKey`. |
| `TaskTree` | Lazily builds the task tree as a graph of `NodeList`/`Node` objects. One `TaskTree` is shared across all changes in a query; each `Node` is refreshed per-change. |
| `TaskTree.Node` | A single task instance in the tree. Holds `Properties` (expanded field values) and cached sub-nodes. Knows whether it is a "change node" (generated by a `change`-type `tasks-factory`). |
| `Properties` | Expands `${property}` placeholders in task fields using an `Expander`. Tracks whether re-expansion is needed (`isApplicableRefreshRequired`, `isSubNodeReloadRequired`, `isTaskRefreshRequired`). |
| `TaskExpression` | Parses a task reference string (e.g. `task-name@file^root`) using the ANTLR4 grammar in `TaskReference.g4`. |
| `MatchCache` / `PredicateCache` | Cache Gerrit query evaluation results per change. `PredicateCache` also determines whether a query result is cacheable by branch only (enabling the `ApplicableNodeFilter` optimization). |

### Sub-node types

A task can grow its sub-node list via four mechanisms (processed by `TaskTree.Node.SubNodeAdder`):

- `sub-tasks` — explicit task references
- `sub-tasks-file` — all tasks in another task file
- `sub-tasks-external` — tasks from another user's ref
- `sub-tasks-factory` — dynamically generates tasks; supports three `names-factory` types: `static`, `change` (one task per matching change), and `plugin` (delegated to a `PluginProvidedTaskNamesFactory` extension point)

### Task statuses

`INVALID, UNKNOWN, DUPLICATE, SKIPPED, WAITING, READY, PASS, FAIL`

Status logic lives in `TaskPluginDefinedInfoFactory.AttributeFactory.getStatusWithExceptions()`.

### Frontend

`gr-task-plugin/` — Polymer 3 web components bundled by Bazel. Entry point is `plugin.js`. The bundle is embedded in the plugin JAR as a resource.

### Extension point

`extensions/PluginProvidedTaskNamesFactory` — other plugins can contribute dynamic task name lists via Guice's `DynamicMap` under the key `<plugin>~<provider>`.

### Testing

- **Unit tests**: `src/test/java/` — standard JUnit4, run with `bazel test :junit-tests`
- **Functional tests**: `test/docker/` — spin up a real Gerrit instance in Docker, push task configs, and verify output via shell scripts (`check_task_statuses.sh`, `check_task_visibility.sh`)
